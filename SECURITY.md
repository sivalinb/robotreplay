# Security and data handling

Do not upload child recordings, credentials, private traces, or provider keys to GitHub issues. Use generated samples to reproduce a problem.

The first deployment is local and authenticated. Shared hosting requires review of TLS, proxy trust, account lifecycle, retention, backups and child-data handling. Team authorization, CSRF protection, bounded processing and output contracts do not constitute a complete managed identity or hostile-media isolation platform.

Report suspected problems privately to the repository owner through an available private contact channel. Public reports should contain only non-sensitive reproduction steps.

Credentials are server-side environment variables. Unknown provider usage remains reserved. Never embed keys in a notebook, screenshot, browser script or benchmark artifact.
